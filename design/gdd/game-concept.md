## 1. 核心識別

| 欄位 | 內容 |
|---|---|
| **Working Title** | TD Wizard |
| **類型** | 3D 動作塔防（Action Tower Defense） |
| **平台** | PC / Steam（Windows 優先） |
| **引擎** | Unity 6000.3.16f1 / URP |
| **連線** | 純單機，無任何線上功能 |
| **視角** | 預設第三人稱，按鍵切換第一人稱（PUBG 式） |
| **核心動詞** | **接通**（Connect）——把塔與塔串成運作中的網路 |
| **主要 MDA 美感** | Challenge（挑戰）；次要 Discovery、Expression |
| **估計規模** | Large（完整版 12–18 個月，單人）／ MVP 3–5 個月 |
| **團隊** | 單人開發，首個完整專案 |

### 電梯簡報

> 你是一名兼任工程師的巫師。在波次推進的戰場上建造防禦塔、嵌入屬性寶石、
> 並用自己的身體作為中繼點，把分散的塔串成連鎖攻擊的網路。
> 你打得不多，但沒有你，整張網就斷了。

### 核心幻想

**「我是這張網路的節點。」**
不是最強的戰士，而是讓整個防禦體系運轉起來的那個人。當連攜因為你的站位而接通、
整條防線同時爆發時，那是你造成的。

### 獨特鉤子

> 像 *Orcs Must Die!*，**而且**你的主要武器是自己的站位與時機，不是法術。

市面上的動作塔防（OMD、Dungeon Defenders）裡玩家是主要輸出來源。
TD Wizard 反轉這點：巫師輸出很弱，價值全在**串起塔**。

**關鍵設定：塔平時完全獨立運作，彼此不會自動連攜。**
連攜攻擊**只能由巫師施放技能觸發**——他把自己當成節點，
將範圍內的複數塔串成一次合體攻擊。沒有巫師，戰場上就只是一堆各自為政的砲台。

因此「**站在哪裡、什麼時候放**」成為核心戰術決策。

## 2. 設計支柱

支柱用於裁決日後所有「要不要加這個功能」的爭論。支柱之間**刻意存在張力**。

### ① 配置勝於操作
> 勝負主要由戰前的寶石配置與塔位決定，而非戰鬥中的反應速度。
>
> **設計測試**：當「提高巫師的操作上限」與「加深配置的選擇空間」衝突時，選後者。

### ② 站位就是資源
> 巫師的所在位置是有限且持續被爭奪的資源——中轉、補強、建造都在搶它。
>
> **設計測試**：任何新增的巫師能力，如果不需要他移動到特定位置才能發揮，就要重新考慮。

### ③ 輕鬆是底色，高潮是點綴
> 主線的**多數**關卡應該是舒服的；每章可有一到兩關作為難度高潮，
> 但絕不設置需要回頭刷等級才能通過的牆。
>
> **設計測試**：當一個機制會讓**每一關**都變緊繃時，把它移進挑戰目標。
> 單關的高潮設計不受此限。

### ④ 一種塔，無限組合
> 內容的增長來自寶石種類與組合，不來自增加塔的種類。
>
> **設計測試**：想加新功能時，先問「這能不能做成一顆寶石？」

### 支柱間的張力（這是設計的平衡點）

- **①×②**：②說「即時站位很重要」，①說「但規劃比操作更重要」。兩者的拉扯定義了
  巫師該有多忙。
- **②×③**：如果站位是持續被消耗的資源，那還輕鬆嗎？這條張力管控巫師的操作負荷上限。

### 反支柱（明確不做）

1. **不做多人連線** — 稀釋單人深度，且時程不允許
2. **不做多種塔型** — 違反支柱④，且炸開美術成本
3. **不做操作技巧門檻**（精準瞄準、連招輸入） — 違反支柱①
4. **不做要求型挑戰目標** — 會產生不可達成的星星（見 §4.3）
5. **不做會卡死進度的難度牆** — 難度高潮可以有，但通關必須靠「想辦法」而非「刷數值」

## 3. 核心循環

### 3.1　30 秒循環（moment-to-moment）

```
巡邏移動 → 讀取塔的狀態 → 判斷：
                            ├─ 這座快撐不住 → 過載 / 護盾 / 維修
                            └─ 連攜技能好了 → 走到能涵蓋最多塔的位置 → 施放
                        → 連攜結束，各塔回歸獨立，技能進 CD
                        → 回到巡邏
```

**手感定位**：戰地指揮官 ＋ 會移動的電路節點。玩家不是在打怪，
是在**判斷何時、在哪裡把這張網接起來**。

**為什麼會好玩**：每幾秒一個小決策，密度剛好；而「站哪裡能涵蓋最多塔」是持續變化的
幾何問題。連攜技能的 CD 讓這個判斷有稀缺性——放早了浪費，放晚了塔已經被打爛。
**站位 × 時機**的雙重決策，是這個循環的核心張力。

**⚠️ 致命前提**：玩家必須能**一眼讀出塔的狀態與連攜可能性**。若需要停下來確認，
整個循環立刻垮掉。資訊設計在此**不是美術問題，是核心玩法問題**。

### 3.2　巫師能力組

> **操作前提**：滑鼠控制視角旋轉（第三、第一人稱皆同），**無自由游標**。
> 目標選取（過載、護盾的指定對象，連攜技能的起點／終點塔）一律透過
> **畫面中心準星 + 自動吸附**完成，
> 不要求精準對位——這是支柱①「配置勝於操作」在操作層的具體落實，
> 而非讓巫師的能力退化為需要瞄準技巧的射擊玩法。完整規格見 art-bible.md §7。

| 能力 | 作用 |
|---|---|
| 基礎攻擊 | 傷害很低，用於自保與補刀漏網小怪 |
| 過載 | 短時間大幅提升單座塔的輸出 |
| 護盾 / 緊急維修 | 保住快被擊毀的關鍵塔 |
| **連攜** ⭐ | **本作招牌機制**。詳見下方 |

#### 連攜技能組（核心機制）

> **塔與塔之間平時不會自動連攜。連攜的唯一來源是巫師施放連攜技能。**

巫師擁有**一組不同的連攜技能**，而非單一通用技能。每個技能各自定義：

| 屬性 | 說明 |
|---|---|
| **起點** | 鏈的起始塔須具備的寶石屬性 |
| **終點** | 鏈的終點塔須具備的寶石屬性 |
| **節點數** | 該技能串接的塔數量（依技能而定，非固定） |
| **效果** | 該組合產生的合體攻擊內容 |

**⚠️ 方向性是關鍵**：`A → 巫師 → B` 與 `B → 巫師 → A` 是**技能清單上兩個不同的技能**，
效果不同。起點與終點不可互換。

```
玩家選擇一個連攜技能
   ↓
確認條件：場上有符合起點／終點屬性的塔，且巫師站位使其落入節點範圍
   ↓
施放 → 一次性的合體攻擊
   ↓
各塔回歸獨立運作，該技能進入 CD
```

**重點特性**：

- **一次性，非持續** — 不是站著維持通道，是放完就結束
- **巫師是鏈上的中繼節點** — 他的位置決定哪些塔能被串進去
- **有方向性** — 起點與終點不同，效果就不同
- **各技能獨立 CD** — 「該用哪一個、什麼時候用」成為有稀缺性的決策

**設計意義：三重鎖**

要發動一次連攜，玩家必須**同時滿足三個條件**：

```
手上有對應的連攜技能  ×  場上有正確屬性的塔  ×  自己站在對的位置
```

這讓支柱①「配置勝於操作」非常具體——玩家是**照著手上有哪些連攜技，
反推該把什麼屬性的塔蓋在哪裡**。寶石配置不再是孤立的數值選擇，
而是為了讓特定連攜技能可用而做的佈局。

同時它實現了核心幻想（「我是這張網路的節點」）與支柱②（「站位就是資源」）：
站位在此不是**停車問題**（停在某處維持連線），而是**時機問題**——
在對的時刻出現在對的位置，放完即自由。後者與「巡邏」這個核心動作相容，
前者會與之打架。

**技能取得**：見 §3.5 長期成長循環（技能樹）。

**建造代價**：建造與嵌合期間，巫師**無法攻擊、無法閃避**，等同活靶。
此代價是動態的——安全時建造沒有成本，戰鬥中建造是拿命在賭。
不設額外的資源懲罰或階段限制。

### 3.3　5 分鐘循環（一場戰鬥）

```
準備期：配置塔、嵌合寶石
   ↓  ← 玩家可主動提前召喚下一波，換取獎勵
波次來襲：巡邏、補強、中轉
   ↓
清完 → 結算金錢 → 回到準備期
```

**節奏掌控權在玩家手上**。自信時提前開波吃獎勵，沒把握就慢慢佈置。

**⚠️ 平衡約束**：提前召喚的獎勵必須是**每波固定值**，不可隨連續衝波累加。
否則最佳解會坍縮成「永遠全速衝」，這個選擇就消失了。

**資源模型**：混合制
- **開場預算**（固定）→ 決定初始佈局
- **擊殺回饋**（動態）→ 供給臨場應變

### 3.4　關卡與章節（session）

| 層級 | 規格 |
|---|---|
| 一關 | 約 5 分鐘，含三個限制型挑戰目標（= 三顆星） |
| 一章 | 數關組成（關卡數不固定），章末給一個寶箱 |
| 額外獎勵 | 章節內每關都達成三星 → 再給一個寶箱 |
| 存檔 | **即時存檔**——進入關卡、完成關卡、點天賦／技能皆存 |

**注意**：主線關卡與星星挑戰是**同一批關卡**。星星是掛在主線關卡上的完成度標示，
不是獨立的挑戰模式。

### 3.5　長期成長循環

```
通關 / 達成星星 → 章末寶箱 → 隨機開出：
                              ├─ 寶石（主要內容軸）
                              ├─ 天賦點數
                              └─ 遊戲內貨幣
                          → 配置空間變大 → 能挑戰更難的星星
```

**貨幣用途**：定向購買特定寶石（補償隨機性）、重置天賦點。
貨幣是**隨機性的保底機制**。

**天賦與難度的關係**：天賦永久生效，回頭打早期關卡會變輕鬆。
這是刻意選擇的 MapleStory 式爽感，不做等級隔離。

#### 天賦介面：兩張圖，一份點數

介面上稱為「天賦樹」，但**內部是兩張各自獨立的樹狀圖**：

| 圖 | 內容 |
|---|---|
| **天賦樹** | 被動加成節點（數值、資源、效率） |
| **技能樹** | **連攜技能節點**——解鎖 §3.2 的各個連攜技 |

**共用同一份點數池。** 這是刻意設計——「這一點要拿去加強被動，
還是多解一個連攜技？」成為真實取捨。兩份獨立點數會讓這個決策消失。

**⚠️ 硬規則：兩張圖的前置關係不可跨樹。**
被動節點的前置只能是被動節點，技能節點的前置只能是技能節點。
兩張圖是不相交的子圖，只是共用點數並呈現在同一介面。

> **為什麼這條不能違反**：它保留了日後把兩者拆成獨立介面的可能性。
> 守住此規則，拆分只是「把一張畫布分成兩張」；違反它，拆分等於重新設計前置關係。
> 至於共用點數池——拆分時需重新平衡，但那是可接受的成本，
> 且共用池帶來的取捨感是確定的收益。

**介面呈現**：兩張圖在視覺上須分開（分頁或左右分區），
不可將技能節點散佈於被動節點之間——視覺相鄰應代表邏輯相關，
否則玩家會對不存在的連線產生錯誤預期。

## 4. 關鍵系統

### 4.1　塔與寶石

**只有一種基礎塔。** 所有變化來自寶石。

- 塔本身無屬性，是空白載體
- 嵌入寶石後獲得屬性與能力
- **寶石種類**是主要深度來源（玩法變化）
- **寶石等級**是次要軸（數值小幅提升），避免數值輾壓

**連攜攻擊**的效果由參與塔的**寶石屬性組合**決定，不是塔種之間的差異
（因為只有一種塔）。不同的屬性組合產生不同的合體攻擊效果。

**再次強調**：連攜不會自動發生，必須由巫師施放技能觸發（見 §3.2）。

### 4.2　挑戰目標模板庫

每關從模板庫挑三個、填入參數，組成該關的三星目標。
**體感是客製的，成本是組合的**——每個模板只需實作一次。

| 模板 | 參數範例 | 考驗什麼 |
|---|---|---|
| 塔數上限 | ≤ 3 座 | 配置效率 |
| 屬性禁用 | 不可使用火寶石 | 替代方案的掌握 |
| 寶石等級上限 | 只能用 Lv1 寶石 | 基礎功而非數值輾壓 |
| 連攜禁用 | 全程不施放連攜技能 | 單塔輸出的理解。因連攜只能由巫師觸發，此模板等於「不用招牌技」 |
| 巫師禁手 | 全程不使用任何主動技能 | 塔組本身的品質 |
| 純預置 | 開戰後不得建造 | 戰前規劃能力 |
| 嵌合鎖定 | 開戰後不可重新嵌合 | 預判能力 |
| 時限 | 90 秒內清完 | 節奏掌控 |
| 無傷 | 目標不得被擊中 | 滴水不漏 |

### 4.3　挑戰目標的鐵則：只用限制型

> **限制型目標永遠可達成；要求型目標可能卡死。**

- ✅ 「**不可**使用火寶石」— 無論玩家擁有什麼寶石都做得到
- ❌ 「**必須**使用風寶石」— 沒抽到風寶石就不可能達成

寶石為隨機掉落，因此挑戰目標**一律使用限制型**。
此規則從根本消除了「隨機掉落 × 固定目標」的衝突，不需額外的保底系統。

## 5. MDA 分析

**Mechanics（機制）**
建造、寶石嵌合、巫師增益（過載／護盾／維修）、**連攜技能組**、主動召喚波次、
三星限制挑戰、天賦樹／技能樹、寶箱

**Dynamics（動態）**
空間網路規劃、風險評估（何時建造 / 何時開波）、配置最佳化、
限制條件下的再創造、屬性剋制的讀取與應對

**Aesthetics（美感）**

| 美感 | 強度 | 來源 |
|---|---|---|
| Challenge | ★★★ | 三星限制挑戰、章末高潮關 |
| Discovery | ★★ | 寶石組合與連攜的探索空間 |
| Expression | ★★ | 個人化的配置風格 |
| Fantasy | ★★ | 巫師工程師的角色幻想 |
| Fellowship | ✗ | 純單機，刻意不做 |

## 6. 玩家動機剖析（自我決定理論）

| 需求 | 強度 | 說明 |
|---|---|---|
| **自主性** | ★★★ | 三層選擇都成立：蓋哪裡、嵌什麼、何時開波。「可主動召喚」讓玩家連節奏都能掌控。 |
| **勝任感** | ★★★ | 雙軌成長——客觀上寶石變多，主觀上越來越懂屬性搭配。三星挑戰提供驗證技巧的標尺。 |
| **關聯性** | ⚠️ 弱 | **已知弱項。** 純單機、無社群，環境敘事受限於 5 分鐘關卡節奏。黏著來自「精通系統」，不會來自「情感連結」。此取捨的完整說明見 §8「明確不服務的族群」。 |

## 7. 心流設計

| 心流要素 | 本作的實現 |
|---|---|
| 難度與能力匹配 | 主線微幅遞增 + 章末高潮；難度主要由玩家自選的星星承載 |
| 明確目標 | 每波目標明確；三星目標在進關前就明示 |
| 即時回饋 | 塔狀態視覺化、連攜觸發特效、擊殺金錢回饋 |
| 控制感 | 可主動召喚下一波——節奏掌控權在玩家 |
| **挫折防護** | **5 分鐘關卡 + 即時存檔 = 極低重試成本。** 挫折感的來源從來不是難度本身，是重試成本。 |

## 8. 目標玩家

### 主要客群：成就型 / 完成主義者
（Bartle: Achievers｜Quantic Foundry: Mastery + Achievement 雙高）

三星系統、寶箱、天賦樹是為「想把每一格填滿」的人設計的。

### 次要客群：理論工匠型（Theorycrafters）

「一種塔 × 多種寶石 × 連攜組合」天然吸引喜歡拆解系統、找最優解的人。
人數不多但黏著極高，且會主動產出攻略與討論。

### 明確不服務的族群

| 類型 | 原因 |
|---|---|
| 社交型 | 純單機，零社交功能 |
| 反應型 | 支柱①排除了操作技巧門檻 |
| 劇情驅動型 | 環境敘事是點綴，不是主體 |
| 討厭最佳化的休閒玩家 | 寶石系統本質要求動腦 |

### 市場驗證

| 參照作品 | 驗證了什麼 |
|---|---|
| Kingdom Rush 系列 | 三星挑戰制塔防，數千萬下載，證明此成就結構有龐大市場 |
| Orcs Must Die! | 動作塔防 + 評分制，成功系列 |
| Bloons TD 6 | 主動召喚下一波、極長尾生命週期 |

**差異化成立**：最接近的 *Orcs Must Die!* 中玩家是主要輸出，
而 TD Wizard 的巫師是「弱輸出 + 連攜技能組」——他不打怪，他把塔串起來。
此定位無直接競品。
「寶石嵌合為唯一成長軸」在塔防類型中亦少見。

## 9. 視覺識別錨點

> 本節是 `/art-bible` 的地基，也是採購美術素材時的篩選標準。
> ⚠️ **完整規格已於 art-bible.md 展開並修訂**（例如原則①精修為「厚重的世界，
> 明亮的魔法」並附具體灰階測試門檻）。本節保留原始錨點供追溯，
> **實作與細節查證一律以 art-bible.md 為準**。

**方向名稱**：明亮奧術（Luminous Arcane）

### 一句話視覺規則

> **屬性先於美感**——任何視覺決策若降低了屬性的辨識速度，就是錯的。

### 支撐原則

**1. 每種屬性有專屬色相，永不共用**
*設計測試*：新增寶石屬性時，若找不到與現有屬性明顯區隔的色相，就不加這個屬性。

**2. 連攜是畫面上最亮的東西**
*設計測試*：連攜觸發時，玩家視線若沒有被自動吸引過去，特效就不夠強。

**3. 場景必須暗於單位**
*設計測試*：把戰鬥畫面轉成灰階，塔與敵人仍須能從背景中分離出來。

### 色彩哲學

中性偏冷的場景（石灰、深藍灰）作為畫布，**所有飽和色彩保留給功能性元素**——
寶石屬性、連攜光束、塔的狀態。玩家看到的每一個鮮豔顏色都必須有意義。

### 美術生產策略

**素材為主，關鍵物件自製或客製。**
場景與敵人採購現成素材；**塔與巫師**（玩家盯最久的兩個物件）自製或客製。

## 12. 風險清單

### 技術風險

| 風險 | 嚴重度 | 說明 |
|---|---|---|
| **連攜技能的可讀性** | 🔴 高 | **第一號風險。** 玩家須在戰鬥中同時判讀三件事：手上有哪幾個連攜技、哪幾個**現在可放**（屬性條件 ＋ 站位條件同時滿足）、每個會串到哪些塔且方向為何。技能庫結構使判讀負擔遠高於單一技能，是本作最需要投資的 UI 問題。 |
| **塔狀態的即時可讀** | 🟠 中高 | 5 分鐘關卡內，玩家要瞥一眼就知道哪座塔需要幫忙。純資訊設計問題。 |
| 敵人數量的效能 | 🟡 中 | 後期單位多，需物件池 / GPU Instancing。有標準解法。 |
| 雙視角的 UI 適配 | 🟢 低（已有初步解法） | art-bible §7 已定小地圖、螢幕邊緣指示器、遮擋描邊等具體方案。殘餘風險僅在於效能與實作細節。 |

### 設計風險

- **「弱輸出」會不會無聊？** 巫師攻擊很弱時，爽感必須全部由增益與連攜的回饋補回來。
  若這些技能的打擊感做不出來，玩家會覺得自己在打空氣。
- **一種塔會不會太單調？** 全靠寶石撐變化。若 5 種寶石差異不夠明顯，MVP 階段就會膩。

### 執行風險（最大）

開發者尚未完成過完整專案，**實際產出速度是未知數**。
因此 MVP 必須小到能完整走完一次「設計 → 實作 → 測試 → 發布」循環，
以取得真實的速度數據，再據以規劃 v1.0。

## 13. 待解問題（交給下游）

1. **「弱輸出」的數值下限** — 太弱玩家覺得基礎攻擊是裝飾品，太強侵蝕塔的地位。
   留給 `/design-system` 的巫師系統 GDD。
2. ~~**連攜中轉 × 建造硬直的互動**~~ — ✅ **已解決（2026-09-16）**
   連攜是**一次性技能**而非持續通道，不存在「長時間站定」的狀態，
   因此不與建造硬直競爭行動力預算。殘留的小問題僅為：施放瞬間是否有短暫動作硬直
   （數值細節，留給巫師能力 GDD）。
3. **手把支援等級** — 原訂 Partial 的理由（魔法陣繪製難以用手把操作）已隨該機制移除而消失。
   可於 `/ux-design` 階段重新評估是否提升為 Full。

| 日期 | 決策 | 理由 |
|---|---|---|
| 2026-09-11 | 移除「繪製魔法陣」機制 | PC 端滑鼠繪圖不現實，戰鬥中需同時走位，體驗綁手 |
| 2026-09-11 | 巫師 = 弱輸出 + 強增益 + 連攜中轉 | 若巫師能自己打爽，寶石與連攜系統會退化成配菜 |
| 2026-09-11 | 全程可建造，代價是喪失行動力 | 動態代價優於固定資源懲罰，遊戲會自行產生平衡 |
| 2026-09-11 | 純單機 | 集中資源做深核心系統；連攜中轉對延遲敏感 |
| 2026-09-13 | 對抗感來自限制型挑戰，而非適應性敵人 | 內容乘法對時程更友善；接受「成就感」取代「博弈感」 |
| 2026-09-13 | 只有一種基礎塔，寶石是唯一內容軸 | 大幅降低美術成本，所有變化由寶石承載 |
| 2026-09-13 | 挑戰目標一律限制型 | 從根本消除「隨機掉落 × 固定目標」的衝突 |
| 2026-09-13 | 第一人稱切換納入 MVP | 開發者確認為體驗核心的一部分 |
| 2026-09-16 | **連攜為一次性技能，非持續通道** | 放完即結束、各塔回歸獨立、技能進 CD。使站位成為「時機問題」而非「停車問題」，與巡邏這個核心動作相容 |
| 2026-09-16 | **引燃連攜與連攜中轉合併為單一技能** | 原文件誤列為兩項能力，實為同一個機制 |
| 2026-09-16 | **塔之間不會自動連攜，巫師是唯一來源** | 最大化巫師的存在感——沒有他，戰場只是一堆獨立砲台。直接強化核心幻想 |
| 2026-09-17 | **連攜是技能組而非單一技能，且有方向性** | 每個連攜技定義起點屬性、終點屬性、節點數、效果。A→B 與 B→A 是兩個不同技能。產生「技能 × 屬性 × 站位」的三重鎖 |
| 2026-09-17 | **連攜技能由技能樹解鎖，與天賦樹共用點數池** | 內部為兩張獨立樹狀圖，介面合一。共用點數使「點被動 vs 點技能」成為真實取捨 |
| 2026-09-17 | **前置關係不可跨樹（硬規則）** | 保留日後拆成獨立介面的可能性。守住則拆分只是分割畫布，違反則須重新設計前置關係 |
