## 1. 核心識別

| 欄位 | 內容 |
|---|---|
| **Working Title** | TD Wizard |
| **類型** | 3D 動作塔防（Action Tower Defense） |
| **平台** | PC / Steam（Windows 優先） |
| **引擎** | Unity 6000.3.16f1 / URP |
| **連線** | 純單機，無任何線上功能 |
| **視角** | 預設第三人稱，按鍵切換第一人稱（PUBG 式） |
| **核心動詞** | **接通**（Connect）——巫師作為中繼點，連接不同的塔，釋放特別的技能 |
| **主要 MDA 美感** | Challenge（挑戰）；次要 Discovery、Expression |
| **估計規模** | Large（完整版 12–18 個月，單人）／ MVP 3–5 個月 |
| **團隊** | 單人開發，首個完整專案 |

### 電梯簡報

> 你是一名兼任工程師的巫師。在波次推進的戰場上建造防禦塔、嵌入屬性寶石、
> 並用自己的身體作為中繼點——走到對的位置，連接起不同屬性的塔，
> 釋放只有那個組合才放得出來的技能。
> 你打得不多，但沒有你，那些塔就只是各自為政的砲台。

### 核心幻想

**「我是這張網路的節點。」**
不是最強的戰士，而是讓整個防禦體系運轉起來的那個人。
兩座塔平時毫無關係——是你站到那裡，它們才產生關係。
當連攜因為你的站位而接通、那一招放出來時，那是你造成的。

### 獨特鉤子

> 像 *Orcs Must Die!*，**而且**你的主要武器是自己的站位與時機，不是法術。

市面上的動作塔防（OMD、Dungeon Defenders）裡玩家是主要輸出來源。
TD Wizard 反轉這點：巫師輸出很弱，價值全在**連接塔**。

**關鍵設定：塔平時完全獨立運作，彼此不會自動連攜。**
連攜**只能由巫師施放技能觸發**——他把自己當成中繼點，
連接範圍內不同屬性的塔，釋放只有該組合才放得出來的技能。
沒有巫師站到那裡，戰場上就只是一堆各自為政的砲台。

> 📌 **「連接」是關係，不是幾何。** 塔被連接起來的產物是**一個技能**，
> 效果落在技能自己決定的位置（地面區域、某隻敵人…），
> **不是一道沿著塔與塔連線跑的光束**。實作與美術皆不得畫出塔之間的連線。

因此「**站在哪裡、什麼時候放**」成為核心戰術決策。

## 2. 設計支柱

支柱用於裁決日後所有「要不要加這個功能」的爭論。支柱之間**刻意存在張力**。

### ① 配置勝於操作
> 勝負主要由戰前的寶石配置與塔位決定，而非戰鬥中的反應速度。
>
> **設計測試**：當「提高巫師的操作上限」與「加深配置的選擇空間」衝突時，選後者。

### ② 站位就是資源
> 巫師的所在位置是有限且持續被爭奪的資源——中轉、補強、建造都在搶它。
>
> **設計測試**：任何新增的巫師能力，如果不需要他移動到特定位置才能發揮，就要重新考慮。

### ③ 輕鬆是底色，高潮是點綴
> 主線的**多數**關卡應該是舒服的；每章可有一到兩關作為難度高潮，
> 但絕不設置需要回頭刷等級才能通過的牆。
>
> **設計測試**：當一個機制會讓**每一關**都變緊繃時，把它移進挑戰目標。
> 單關的高潮設計不受此限。

### ④ 一種塔，無限組合
> 內容的增長來自寶石種類與組合，不來自增加塔的種類。
>
> **設計測試**：想加新功能時，先問「這能不能做成一顆寶石？」

### 支柱間的張力（這是設計的平衡點）

- **①×②**：②說「即時站位很重要」，①說「但規劃比操作更重要」。兩者的拉扯定義了
  巫師該有多忙。
- **②×③**：如果站位是持續被消耗的資源，那還輕鬆嗎？這條張力管控巫師的操作負荷上限。

### 反支柱（明確不做）

1. **不做多人連線** — 稀釋單人深度，且時程不允許
2. **不做多種塔型** — 違反支柱④，且炸開美術成本
3. **不做操作技巧門檻**（精準瞄準、連招輸入） — 違反支柱①
4. **不做要求型挑戰目標** — 會產生不可達成的星星（見 §4.3，含抗性佈局的限定）
5. **不做會卡死進度的難度牆** — 難度高潮可以有，但通關必須靠「想辦法」而非「刷數值」

## 3. 核心循環

### 3.1　30 秒循環（moment-to-moment）

```
巡邏移動 → 讀取塔的狀態 → 判斷：
                            ├─ 這座快撐不住 → 過載 / 護盾 / 維修
                            └─ 連攜技能好了 → 走到配方成立的位置
                                            → 按技能進入施法模式 → 選目標 → 施放
                        → 技能進 CD
                        → 回到巡邏
```

**手感定位**：戰地指揮官 ＋ 會移動的電路節點。玩家不是在打怪，
是在**判斷何時、在哪裡把這張網接起來**。

**為什麼會好玩**：每幾秒一個小決策，密度剛好。

站位的第一層意義對**所有**連攜技都成立——**站哪裡才讓配方成立**（哪些塔進得了範圍）。
部分技能還有第二層：**站哪裡才讓效果落得到敵人**（落點圓的圓心由巫師與參與塔共同決定，
巫師往前走，圓就往前移）。兩層常常互相拉扯——能開出配方的位置未必打得到敵人。

連攜技能的 CD 讓這個判斷有稀缺性——放早了浪費，放晚了塔已經被打爛。
**站位 × 時機**的雙重決策，是這個循環的核心張力。

**⚠️ 致命前提**：玩家必須能**一眼讀出塔的狀態與連攜可能性**。若需要停下來確認，
整個循環立刻垮掉。資訊設計在此**不是美術問題，是核心玩法問題**。

### 3.2　巫師能力組

> **操作前提**：滑鼠控制視角旋轉（第三、第一人稱皆同），**無自由游標**。
> 目標選取（過載、護盾的指定對象，連攜技能的目標——**各技能自訂，可能是地面落點或特定敵人**）一律透過
> **畫面中心準星 + 自動吸附**完成，
> 不要求精準對位——這是支柱①「配置勝於操作」在操作層的具體落實，
> 而非讓巫師的能力退化為需要瞄準技巧的射擊玩法。完整規格見 art-bible.md §7。

| 能力 | 作用 |
|---|---|
| 基礎攻擊 | 傷害很低，用於自保與補刀漏網小怪 |
| 過載 | 短時間大幅提升單座塔的輸出 |
| 護盾 / 緊急維修 | 保住快被擊毀的關鍵塔 |
| **連攜** ⭐ | **本作招牌機制**。詳見下方 |

#### 連攜技能組（核心機制）

> **塔與塔之間平時不會自動連攜。連攜的唯一來源是巫師施放連攜技能。**

巫師擁有**一組不同的連攜技能**，而非單一通用技能。

**巫師是中繼點，連接不同的塔，釋放特別的技能。**

塔是**被連接的對象**，不是攻擊的發起者。連接的產物是一個技能，
**效果不沿著塔與塔的連線發生**——落在哪裡由該技能自己定義。

#### ⚠️ 每個連攜技都是獨立的表現方式

> **連攜技能不是某種固定形式的變體。** 每一招有自己的目標方式、自己的推進節奏、
> 自己的演出。**不要為它們建立分類系統**——
> 「領域型／標記型」這種歸納會在第四招出現時就崩壞，而 v1.0 要擴到 10+ 招。

因此規格分成兩層：**所有連攜技共通的不變式**，與**各技能自己定義的部分**。

**不變式（全部連攜技都必須遵守，資料模型的硬骨架）**

| 項目 | 規則 |
|---|---|
| 觸發來源 | 只能由巫師施放。塔之間永遠不會自動連攜 |
| 施放條件 | 巫師範圍內湊得出該技能的**配方**（屬性 × 固定數量） |
| 塔的角色 | **材料**。提供施放資格，本身行為完全不變，不中斷自己的攻擊 |
| 階段數 | **兩個階段，有先後**（見下方「方向性 ＝ 順序」） |
| 施法模式 | 不能移動；移動或受擊即取消、無代價 |
| 前搖 | 確認後 0.3 秒可被打斷 → 短僵直，技能不進 CD |
| 霸體 | 前搖結束後不可打斷 |
| CD | 各技能獨立計算 |

**各技能自訂（不設限，資料模型須容納未知形態）**

| 項目 | 說明 |
|---|---|
| **目標方式** | 地面區域？單一敵人？某條路徑？其他？由該技能自己定義 |
| **是否受落點圓約束** | **逐技能宣告**，不由形態推導 |
| **階段如何推進** | 計時自動？條件觸發？混合？由該技能自己定義 |
| **效果與時長** | 完全自由 |
| **是否使用染色** | 選用，見下方說明 |

> 📌 **對資料模型的要求**：不可用列舉型別把形態寫死
> （`enum SkillForm { Area, Mark }` 是錯的）。
> 目標方式與階段推進條件須為**可擴充的策略物件**，新增一招不該需要改動既有型別。

> ⚠️ **落點圓與支柱②（須明確記載，否則會被誤判為違規）**
>
> 支柱②的設計測試是「不需要移動到特定位置就能發揮的能力，要重新考慮」。
> 部分技能（如 ③ 星星之火）的準心不受落點圓約束，看似違反——
> 但**施放條件未變**：巫師仍必須站在配方要求的塔全部進入範圍的位置。
> **站位決定「能不能放」，只是該技能不再由站位決定「打哪裡」。**
>
> 這類技能把空間決策從**即時站位**移到**戰前佈局**（那座塔蓋在哪、敵人會不會經過），
> 那是支柱①的主場。**這是拿支柱②換支柱①的刻意交換，不是放棄。**
>
> 限制：MVP 只有一招這樣。**若不受落點圓約束的技能變成多數，支柱②會被實質架空**，
> 屆時須回頭重審本節。這是需要持續盯的比例，不是一次性的例外。

**⚠️ 方向性 ＝ 順序**

`火 → 霜` 與 `霜 → 火` 是**技能清單上兩個不同的技能**。
**起點屬性的表現先發生，終點屬性的表現後發生。**

> 📌 **染色是選用手段，不是方向性的定義。**
> 某些技能用「階段1 賦予屬性 → 階段2 以剋制屬性打」產生 combo（如炎寒領域），
> 某些技能純粹是表現順序（如凍土的熔岩 → 冷卻）。兩種都合法。

**能產生染色 combo 的方向只有 5 組**——即相剋環的 5 條邊反讀：
`霜→火`、`雷→霜`、`風→雷`、`蝕→風`、`火→蝕`。
其餘方向的階段 2 打不出剋制，因此若要走反方向，該技能就不該依賴傷害
（見 MVP 技能 ②）。

#### MVP 的三個連攜技

> **起始寶石因此定為火、霜、風**——三個技能第一關即全部可用。
> 雷與蝕在 MVP 無對應連攜技（3 個技能最多覆蓋 3–4 種屬性，此為數學極限），
> 但仍是可用的塔寶石。

**① 霜 → 火「炎寒領域」**｜配方：霜×1 ＋ 火×1｜目標：地面區域，**受落點圓約束**

```
階段1（2秒）暴風雪  賦予經過的敵人「霜」屬性 ＋ 緩速
階段2（2秒）火海    火剋霜 ×1.5，並額外造成巫師基本傷害的一定 % 數
```
角色：**爆發傷害**。認知模式：**反應型**——看到怪群就放。

**② 火 → 霜「凍土」**｜配方：火×1 ＋ 霜×1｜目標：地面區域，**受落點圓約束**

```
階段1（2秒）熔岩    經過者受灼燒。此技能唯一的傷害來源
階段2（瞬間）冷卻成岩石
                    以 t=2.0 的快照判定：當下站在熔岩上的敵人定身 1.5 秒
                    定身期間受攻擊不解除
                    岩石僅為地面視覺變化，不阻擋路徑，未被控到的敵人照常通行
```
角色：**灼燒 ＋ 硬控**。認知模式：**預判型**——要算兩秒後敵人在哪。

> **不染色。** 走的是「火剋霜」的反方向，階段2 打不出剋制，
> 因此刻意不依賴傷害——價值全在控制。

**③ 火 → 風「星星之火」**｜配方：火×1 ＋ 風×1｜目標：單一敵人，**不受落點圓約束**

```
階段1  準心遠距離點燃一隻敵人，使其進入「火種」狀態（有時限，過期消失）
階段2  當該敵人遭受風屬性攻擊時觸發：
       瞬間引爆為大火，對其自身與路徑後方一定距離內的敵人
       造成持續 5 秒的灼燒
```
角色：**延遲引爆**。認知模式：**佈局型**——你的風塔在哪決定它有沒有用。

> **「火種」是獨立標記，不是 `AppliedAttribute`。**
> 不寫入屬性欄位，因此不會讓蝕塔額外吃 ×1.5，也不會覆寫菁英怪的原生屬性。
>
> **這是三個技能裡最貼核心動詞「接通」的一個**——巫師標記、塔引爆，
> 兩邊真的接上了才有效果。前兩個技能中，塔只是入場券。

#### 施放流程

```
按下技能鍵
   ↓
【施法模式】巫師不能移動，用準心選定該技能的目標
            （目標方式由技能自訂：地面區域、特定敵人…）
   ├─ 移動      → 取消，無代價
   └─ 受到攻擊  → 取消，無代價
   ↓ 確認施放
【前搖 0.3 秒】可被攻擊打斷 → 短僵直，技能不進 CD
   ↓
【霸體】不可打斷 → 技能效果生效 → 技能進 CD
```

**可釋放圓**——**逐技能宣告是否適用**，不由形態推導：

```
圓心 ＝ 參與的塔與巫師的幾何中點
半徑 ＝ 參與塔之中射程最長者的攻擊半徑
```

對受此約束的技能（如 ①②），巫師往前站，圓就往前移——
**站位不只決定「能不能放」，更決定「能放到哪」。**

對不受約束的技能（如 ③），準心所及皆可，不畫圓。

> **施法模式的其餘規則對所有連攜技完全相同**——不能移動、移動或受擊即取消、
> 前搖 0.3 秒可打斷、之後霸體。差異只在「目標怎麼選」。

> ⚠️ **硬性設計約束**：施法模式的目標停留時間 **≤ 1 秒**。
> 由於受擊即取消，若選落點需要仔細瞄準，連攜會在怪群密集時（最需要它的時刻）
> 最難放出來。準心的預設落點必須一進入施法模式就已經是合理解。
> 此項須由 `/prototype --spike` 實測驗證。

**重點特性**：

- **巫師一次性施放** — 放完即自由，**不需站著維持**。效果持續多久由技能自訂
- **塔是材料** — 提供施放資格，本身不改變行為，不中斷自己的攻擊
- **有方向性** — 順序不同，效果就不同
- **各技能獨立 CD** — 「該用哪一個、什麼時候用」成為有稀缺性的決策

**設計意義：三重鎖**

要發動一次連攜，玩家必須**同時滿足三個條件**：

```
手上有對應的連攜技能  ×  場上有配方要求的塔  ×  自己站在對的位置
```

這讓支柱①「配置勝於操作」非常具體——玩家是**照著手上有哪些連攜技，
反推該把什麼屬性的塔蓋在哪裡**。寶石配置不再是孤立的數值選擇，
而是為了讓特定連攜技能可用而做的佈局。

同時它實現了核心幻想（「我是這張網路的節點」）與支柱②（「站位就是資源」）：
**巫師必須把自己移動到配方成立的位置，連攜才發生得了**——
沒有他站到那裡，那幾座塔就只是各自為政的砲台。這是「節點」的字面意義，
且**對所有連攜技都成立**，不依賴落點圓（部分技能不受其約束）。

但站位在此不是**停車問題**（停在某處維持連線），而是**時機問題**——
在對的時刻出現在對的位置，放完即自由。後者與「巡邏」這個核心動作相容，
前者會與之打架。

**技能取得**：見 §3.5 長期成長循環（技能樹）。

**建造代價**：建造與嵌合期間，巫師**無法攻擊、無法閃避**，等同活靶。
此代價是動態的——安全時建造沒有成本，戰鬥中建造是拿命在賭。
不設額外的資源懲罰或階段限制。

### 3.3　5 分鐘循環（一場戰鬥）

```
準備期：配置塔、嵌合寶石
   ↓  ← 玩家可主動提前召喚下一波，換取獎勵
波次來襲：巡邏、補強、中轉
   ↓
清完 → 結算金錢 → 回到準備期
```

**節奏掌控權在玩家手上**。自信時提前開波吃獎勵，沒把握就慢慢佈置。

**⚠️ 平衡約束**：提前召喚的獎勵必須是**每波固定值**，不可隨連續衝波累加。
否則最佳解會坍縮成「永遠全速衝」，這個選擇就消失了。

**資源模型**：混合制
- **開場預算**（固定）→ 決定初始佈局
- **擊殺回饋**（動態）→ 供給臨場應變

### 3.4　關卡與章節（session）

| 層級 | 規格 |
|---|---|
| 一關 | 約 5 分鐘，含三個限制型挑戰目標（= 三顆星） |
| 一章 | 數關組成（關卡數不固定），章末給一個寶箱 |
| 額外獎勵 | 章節內每關都達成三星 → 再給一個寶箱 |
| 存檔 | **即時存檔**——進入關卡、完成關卡、點天賦／技能皆存 |

**注意**：主線關卡與星星挑戰是**同一批關卡**。星星是掛在主線關卡上的完成度標示，
不是獨立的挑戰模式。

### 3.5　長期成長循環

```
通關 / 達成星星 → 章末寶箱 → 隨機開出：
                              ├─ 寶石（主要內容軸）
                              ├─ 天賦點數
                              └─ 遊戲內貨幣
                          → 配置空間變大 → 能挑戰更難的星星
```

**貨幣用途**：定向購買特定寶石（補償隨機性）、重置天賦點。
貨幣是**隨機性的保底機制**。

**天賦與難度的關係**：天賦永久生效，回頭打早期關卡會變輕鬆。
這是刻意選擇的 MapleStory 式爽感，不做等級隔離。

#### 天賦介面：兩張圖，一份點數

介面上稱為「天賦樹」，但**內部是兩張各自獨立的樹狀圖**：

| 圖 | 內容 |
|---|---|
| **天賦樹** | 被動加成節點（數值、資源、效率） |
| **技能樹** | **連攜技能節點**——解鎖 §3.2 的各個連攜技，以及可疊加的連攜強化節點 |

#### 可疊加節點（「禁止填充節點」的唯一例外）

§10 規定每個天賦節點都要有明顯體感差異，禁止「+5% 傷害」型填充節點。
**唯一例外是可重複投點的成長節點**：

```
連攜精通  ●○○○○   每級 +X%，可投 5 點
```

它佔**一個**節點格，吸收多點，提供緩慢而可預期的數值成長。

> **為什麼這不算填充**：原規則針對的是「用一堆各自無感的節點灌水湊數量」。
> 可疊加節點只佔一格、明確標示為數值軸、且玩家清楚知道自己在買什麼。
> 它同時解決了 v1.0 的平衡問題——當連攜技擴充到 10+ 個時，
> 大幅階梯式加成會失控，小幅可疊加的成長才撐得住。
>
> **限制**：每張圖至多 2 個可疊加節點，避免例外吃掉規則。

**共用同一份點數池。** 這是刻意設計——「這一點要拿去加強被動，
還是多解一個連攜技？」成為真實取捨。兩份獨立點數會讓這個決策消失。

**⚠️ 硬規則：兩張圖的前置關係不可跨樹。**
被動節點的前置只能是被動節點，技能節點的前置只能是技能節點。
兩張圖是不相交的子圖，只是共用點數並呈現在同一介面。

> **為什麼這條不能違反**：它保留了日後把兩者拆成獨立介面的可能性。
> 守住此規則，拆分只是「把一張畫布分成兩張」；違反它，拆分等於重新設計前置關係。
> 至於共用點數池——拆分時需重新平衡，但那是可接受的成本，
> 且共用池帶來的取捨感是確定的收益。

**介面呈現**：兩張圖在視覺上須分開（分頁或左右分區），
不可將技能節點散佈於被動節點之間——視覺相鄰應代表邏輯相關，
否則玩家會對不存在的連線產生錯誤預期。

## 4. 關鍵系統

### 4.1　塔與寶石

**只有一種基礎塔。** 所有變化來自寶石。

- 塔本身無屬性，是空白載體
- 嵌入寶石後獲得屬性與能力
- **寶石種類**是主要深度來源（玩法變化）
- **寶石等級**是次要軸（數值小幅提升），避免數值輾壓

**連攜技能**由參與塔的**寶石屬性組合**決定，不是塔種之間的差異（因為只有一種塔）。
不同的屬性組合對應不同的連攜技，**且順序也算**——火＋霜有兩招（見 §3.2 方向性）。

**再次強調**：連攜不會自動發生，必須由巫師施放技能觸發（見 §3.2）。

### 4.2　挑戰目標模板庫

每關從模板庫挑三個、填入參數，組成該關的三星目標。
**體感是客製的，成本是組合的**——每個模板只需實作一次。

| 模板 | 參數範例 | 考驗什麼 |
|---|---|---|
| 塔數上限 | ≤ 3 座 | 配置效率 |
| 屬性禁用 | 不可使用火寶石 | 替代方案的掌握 |
| 寶石等級上限 | 只能用 Lv1 寶石 | 基礎功而非數值輾壓 |
| 連攜禁用 | 全程不施放連攜技能 | 單塔輸出的理解。因連攜只能由巫師觸發，此模板等於「不用招牌技」 |
| 巫師禁手 | 全程不使用任何主動技能 | 塔組本身的品質 |
| 純預置 | 開戰後不得建造 | 戰前規劃能力 |
| 嵌合鎖定 | 開戰後不可重新嵌合 | 預判能力 |
| 時限 | 90 秒內清完 | 節奏掌控 |
| 無傷 | 目標不得被擊中 | 滴水不漏 |

### 4.3　挑戰目標的鐵則：只用限制型

> **限制型目標永遠可達成；要求型目標可能卡死。**

- ✅ 「**不可**使用火寶石」— 無論玩家擁有什麼寶石都做得到
- ❌ 「**必須**使用風寶石」— 沒抽到風寶石就不可能達成

寶石為隨機掉落，因此挑戰目標**一律使用限制型**。
此規則從根本消除了「隨機掉落 × 固定目標」的衝突，不需保底掉落系統。

> ⚠️ **限定（2026-09-20 修訂，來源：`/design-review design/gdd/gem-socketing.md`）**
>
> 本鐵則的效力範圍是**挑戰目標本身**，不涵蓋關卡的敵人抗性佈局。
> 兩者相乘時仍可能產生實質上不可達成的星星：
>
> ```
> 挑戰「不可使用火」 ＋ 該關敵人抗霜、抗雷
>   → 玩家剩下的可行解只有風與蝕
>   → 若玩家恰好未持有這兩種，或它們不適合該關卡的路徑結構
>   → 理論上打得動（抗性為 ×0.75，非免疫），但可能打不完時限
> ```
>
> 因此**仍需一道關卡設計驗證規則**（非保底掉落系統，是關卡驗證）：
> 每個關卡的「敵人抗性佈局 × 挑戰禁用項」組合，須至少留下兩種可行的屬性解，
> 其中一種須為玩家在該進度點理論上已可能持有的種類。
>
> 完整規則定義於 [gem-socketing.md](gem-socketing.md) → Edge Cases → 屬性剋制。
> 三星挑戰系統與關卡章節進程的 GDD **必須實作此驗證**，不得僅依賴本節的鐵則。

## 8. 目標玩家

### 主要客群：成就型 / 完成主義者
（Bartle: Achievers｜Quantic Foundry: Mastery + Achievement 雙高）

三星系統、寶箱、天賦樹是為「想把每一格填滿」的人設計的。

### 次要客群：理論工匠型（Theorycrafters）

「一種塔 × 多種寶石 × 連攜組合」天然吸引喜歡拆解系統、找最優解的人。
人數不多但黏著極高，且會主動產出攻略與討論。

### 明確不服務的族群

| 類型 | 原因 |
|---|---|
| 社交型 | 純單機，零社交功能 |
| 反應型 | 支柱①排除了操作技巧門檻 |
| 劇情驅動型 | 環境敘事是點綴，不是主體 |
| 討厭最佳化的休閒玩家 | 寶石系統本質要求動腦 |

### 市場驗證

| 參照作品 | 驗證了什麼 |
|---|---|
| Kingdom Rush 系列 | 三星挑戰制塔防，數千萬下載，證明此成就結構有龐大市場 |
| Orcs Must Die! | 動作塔防 + 評分制，成功系列 |
| Bloons TD 6 | 主動召喚下一波、極長尾生命週期 |

**差異化成立**：最接近的 *Orcs Must Die!* 中玩家是主要輸出，
而 TD Wizard 的巫師是「弱輸出 + 連攜技能組」——他不打怪，他把塔串起來。
此定位無直接競品。
「寶石嵌合為唯一成長軸」在塔防類型中亦少見。

## 9. 視覺識別錨點

> 本節是 `/art-bible` 的地基，也是採購美術素材時的篩選標準。
> ⚠️ **完整規格已於 art-bible.md 展開並修訂**（例如原則①精修為「厚重的世界，
> 明亮的魔法」並附具體灰階測試門檻）。本節保留原始錨點供追溯，
> **實作與細節查證一律以 art-bible.md 為準**。

**方向名稱**：明亮奧術（Luminous Arcane）

### 一句話視覺規則

> **屬性先於美感**——任何視覺決策若降低了屬性的辨識速度，就是錯的。

### 支撐原則

**1. 每種屬性有專屬色相，永不共用**
*設計測試*：新增寶石屬性時，若找不到與現有屬性明顯區隔的色相，就不加這個屬性。

**2. 連攜是畫面上最亮的東西**
*設計測試*：連攜觸發時，玩家視線若沒有被自動吸引過去，特效就不夠強。

**3. 場景必須暗於單位**
*設計測試*：把戰鬥畫面轉成灰階，塔與敵人仍須能從背景中分離出來。

### 色彩哲學

中性偏冷的場景（石灰、深藍灰）作為畫布，**所有飽和色彩保留給功能性元素**——
寶石屬性、連攜光束、塔的狀態。玩家看到的每一個鮮豔顏色都必須有意義。

### 美術生產策略

**素材為主，關鍵物件自製或客製。**
場景與敵人採購現成素材；**塔與巫師**（玩家盯最久的兩個物件）自製或客製。

## 10. MVP 定義

**MVP 要回答的問題**：「巡邏 + 中轉 + 寶石嵌合」這組核心循環是否有趣？

| 項目 | MVP 規格 |
|---|---|
| 章節／關卡 | 1 章，6 關 |
| 寶石種類 | 5 種 |
| 連攜技能 | 3 個（含至少一組方向相反的技能，讓玩家體會方向性）。**配方一律 ×1**，數量要求留給 v1.0 |
| 天賦介面節點 | **10 個 = 約 6 被動 + 4 技能**（每個都要有明顯體感差異，禁止「+5% 傷害」型填充節點；唯一例外是可疊加節點，見 §3.5） |
| 挑戰模板 | 6 個 |
| 視角 | 第三人稱 + 第一人稱切換（**已確認納入 MVP**） |
| 巫師基本傷害 | **固定常數，不成長**。連攜的 %數傷害以此為基準單位 |
| 裝備系統 | ❌ **不做**（列入 v1.0）。MVP 的成長全部來自天賦／技能樹與寶石 |
| 敘事 | 塔／寶石圖鑑文字 |
| 估時 | 3–5 個月 |

## 11. 範圍分層

| | MVP | v1.0 完整版 | 夢想版 |
|---|---|---|---|
| 章節／關卡 | 1 章 6 關 | 4–6 章 30 關 | + 無盡模式 |
| 寶石種類 | 5 | 12–15 | + 稀有寶石 |
| 連攜技能 | 3（配方全 ×1） | 10+（含數量要求配方） | |
| 天賦介面節點 | 10（6 被動 + 4 技能） | 25–30 | |
| 挑戰模板 | 6 | 9 | |
| **裝備系統** | ❌ 不做 | ✅ **關卡隨機掉落，依章節分等級層**（如 1–5 關掉 5 等、6–10 關掉 10 等）。巫師基本傷害由此成長，連帶提升所有連攜技的 %數傷害 | + 套裝／詞綴 |
| 敘事 | 圖鑑文字 | + 章節場景敘事 | |
| 估時（累計） | 3–5 個月 | 12–18 個月 | — |

> **裝備系統的設計理由**：它服務的是 `/brainstorm` 階段記錄的核心動機——
> 「花很多時間讓角色升等的感覺」「只要願意花時間就會慢慢變強」（MapleStory 式累積）。
> 目前的設計裡天賦樹是**選擇軸**（有限點數的取捨），沒有任何東西擔任**累積軸**。
> 裝備補的是這個缺口，不是額外的功能堆疊。
>
> **為什麼不進 MVP**：MVP 只有 6 關，展不開兩個等級層；且裝備不在待驗證的核心循環內。

## 12. 風險清單

### 技術風險

| 風險 | 嚴重度 | 說明 |
|---|---|---|
| **連攜技能的可讀性** | 🔴 高 | **第一號風險。** 玩家須在戰鬥中同時判讀三件事：手上有哪幾個連攜技、哪幾個**現在可放**（屬性條件 ＋ 站位條件同時滿足）、每個會串到哪些塔且方向為何。技能庫結構使判讀負擔遠高於單一技能，是本作最需要投資的 UI 問題。 |
| **塔狀態的即時可讀** | 🟠 中高 | 5 分鐘關卡內，玩家要瞥一眼就知道哪座塔需要幫忙。純資訊設計問題。 |
| 敵人數量的效能 | 🟡 中 | 後期單位多，需物件池 / GPU Instancing。有標準解法。 |
| 雙視角的 UI 適配 | 🟢 低（已有初步解法） | art-bible §7 已定小地圖、螢幕邊緣指示器、遮擋描邊等具體方案。殘餘風險僅在於效能與實作細節。 |

### 設計風險

- **「弱輸出」會不會無聊？** 巫師攻擊很弱時，爽感必須全部由增益與連攜的回饋補回來。
  若這些技能的打擊感做不出來，玩家會覺得自己在打空氣。
- **一種塔會不會太單調？** 全靠寶石撐變化。若 5 種寶石差異不夠明顯，MVP 階段就會膩。

### 執行風險（最大）

開發者尚未完成過完整專案，**實際產出速度是未知數**。
因此 MVP 必須小到能完整走完一次「設計 → 實作 → 測試 → 發布」循環，
以取得真實的速度數據，再據以規劃 v1.0。

## 13. 待解問題（交給下游）

1. **「弱輸出」的數值下限** — 太弱玩家覺得基礎攻擊是裝飾品，太強侵蝕塔的地位。
   留給 `/design-system` 的巫師系統 GDD。
2. ~~**連攜中轉 × 建造硬直的互動**~~ — ✅ **已解決（2026-09-16）**
   連攜是**一次性技能**而非持續通道，不存在「長時間站定」的狀態，
   因此不與建造硬直競爭行動力預算。殘留的小問題僅為：施放瞬間是否有短暫動作硬直
   （數值細節，留給巫師能力 GDD）。
3. **手把支援等級** — 原訂 Partial 的理由（魔法陣繪製難以用手把操作）已隨該機制移除而消失。
   可於 `/ux-design` 階段重新評估是否提升為 Full。
