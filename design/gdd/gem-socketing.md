# 寶石嵌合系統 — Gem Socketing

> **Status**: In Design
> **Author**: 開發者 + Claude（無 specialist agent，本機未安裝）
> **Last Updated**: 2026-09-18
> **Implements Pillar**: ④ 一種塔，無限組合（主要）｜① 配置勝於操作
> **Review Mode**: lean

## Overview

寶石嵌合是 TD Wizard 的**內容軸**。遊戲只有一種基礎防禦塔——它本身能攻擊
（通用單體攻擊，鎖定第一隻敵人），但沒有屬性、也沒有戰術特色。嵌入寶石後，
塔的攻擊機制、索敵邏輯、攻速與屬性標籤**全部由寶石接管**，該塔隨即特化為
五種戰術角色之一：範圍灼燒、減速場、鏈式跳彈、群體擊退、單體穿甲。

寶石採**實例制**——每顆寶石是獨立物件，各自持有等級。玩家可同時擁有同屬性的
多顆寶石且等級不同，嵌合時需選擇使用哪一顆。這使配置決策分為三層：

```
蓋不蓋塔      → 不受限
特化哪幾座    → 受寶石數量限制
特化到多好    → 受寶石等級限制
```

升級採**融合**：消耗 3 顆同屬性 Lv1 換取 1 顆 Lv2，產生「數量 vs 品質」的取捨。
等級僅提供小幅數值提升，刻意不足以壓過屬性選擇本身。

此系統同時是**連攜系統的前提**——連攜技能以「起點屬性 → 終點屬性」定義，
場上若無對應屬性的塔，該技能無法發動。寶石配置因此不只決定單塔輸出，
更決定玩家能使用哪些連攜技。

## Player Fantasy

> **「我在決定哪些塔值得被賦予力量。」**

塔隨時能蓋，但寶石有限、嵌合要錢。玩家站在防線前，腦中跑的是
「這個轉角值得放我唯一那顆 Lv2 的蝕嗎？還是留給後面那個更窄的路口？」
——每一次嵌合都是在分配稀缺資源。

滿足感來自**看懂局面後做出正確配置**，而非操作技巧。當玩家發現
「霜放入口、蝕放轉角、火放窄道」能清掉一波原本擋不住的敵人，
那一刻的感受是**我想通了**，不是**我反應夠快**。

這直接服務支柱①（配置勝於操作）。寶石系統的每個設計——實例制的稀缺、
索敵內建、嵌合有成本——都在把注意力推向戰前思考。

## Detailed Design

### Core Rules

1. **每座塔有且僅有一個寶石插槽。**
2. **基礎塔（未嵌合）具備攻擊能力**：通用單體攻擊、索敵「第一隻」、基準攻速、
   **無屬性**（不觸發弱點，也不受抗性影響）。
3. **嵌入寶石後，寶石完全接管四項特性**：攻擊機制、索敵邏輯、攻速、屬性標籤。
   基礎攻擊被**取代**，非疊加。
4. **索敵邏輯內建於屬性，玩家不可切換。** 不提供「打最前／最後／最強」的手動設定。
5. **寶石採實例制。** 每顆寶石是獨立物件，各自持有等級。
   可同時擁有同屬性多顆不同等級的寶石。
6. **一顆寶石同時只能嵌在一座塔上。**
7. **嵌合需支付費用 `C`**（關卡內金錢），準備期與戰鬥期同價。
8. **塔被摧毀或主動拆除時，寶石自動回收至庫存。寶石永不損毀。**

#### 基礎塔規格 ⚠️ provisional（待塔系統 GDD 確認）

| 項目 | 值 |
|---|---|
| 攻擊機制 | 通用單體投射物 |
| 索敵 | 第一隻（最接近目標的敵人） |
| 攻速 | 基準值（1.0×，其他屬性以此為比較基準） |
| 屬性 | **無** |

> 基礎塔的定位是**可用但平庸**，同時是**預算選項**——錢少時多蓋幾座基礎塔，
> 錢多時少蓋但嵌好寶石。
>
> 「無屬性」意味著它面對高抗性敵人時反而穩定（不吃 ×0.75），
> 但也永遠吃不到 ×1.5 的弱點加成。

#### 五種寶石規格

| 功能名 | 寶石名 | 色相 | 類型 | 索敵 | 攻擊機制 | 攻速 |
|---|---|---|---|---|---|---|
| **火** | 爐心石 | 橙紅 25° | 區域 | 射程內隨機敵人 | 週期性投放固定範圍燃燒區，持續數秒 | 中 |
| **霜** | 凍泉晶 | 青 190° | 區域 | 射程最前緣（固定） | 持續維持減速場，敵人進入時受一次性傷害 | 持續 |
| **雷** | 鐘鳴石 | 黃 55° | 指向 | 第一隻 → 跳躍 | 鏈式跳彈，4 次跳躍，**可重複命中同一目標**，每跳 −20% | 中 |
| **風** | 風信石 | 綠 130° | 指向 | 最前排數隻 | 群體小幅擊退，**距離隨機**，不疊加 | 快 |
| **蝕** | 鏽紋紫晶 | 紫 285° | 指向 | **固定第一隻，不越位** | 單體重擊，附加穿甲 debuff | 慢 |

**類型分野**：火與霜是**場域型**（放置後持續作用），雷、風、蝕是**指向型**。

**角色不重疊檢查**
```
基礎  → 打「最前面的」，通用無特色
火    → 打「聚在一起的」
霜    → 打「剛進場的」，並拖慢
雷    → 打「排成串的」
風    → 打「最前面的」，推回去
蝕    → 打「最前面的」，讓他變脆
```
基礎、風、蝕同樣盯最前排，但基礎是普通輸出、風延後抵達時間、蝕加速死亡。

### States and Transitions

| 狀態 | 說明 | 可轉換至 |
|---|---|---|
| `Empty` | 已建造，未嵌合。使用基礎攻擊 | `Socketed` |
| `Socketed` | 已嵌合，寶石接管所有攻擊特性 | `Empty`（取下）、`Socketed`（替換） |

#### 嵌合經濟模型

只有**單一成本參數 `C`**，階段差異由退款政策產生：

| 操作 | 準備期 | 戰鬥期 |
|---|---|---|
| **嵌入** | 花費 `C` | 花費 `C` |
| **取下** | **全額退還 `C`** → 淨成本 0 | **不退還** → 損失 `C` |
| **替換** | 退舊付新 → 淨成本 0 | 損失舊的 `C` + 付新的 `C` |
| 塔被摧毀 | — | 寶石回收，**嵌入費不退還** |

> **設計意圖**：
> - 準備期實驗仍然免費——可無限次試裝、拆掉、換一顆，淨成本為零
> - 戰鬥期改配置真的痛——除建造硬直的風險外，還會白白損失已投入的錢
> - 塔被摧毀時嵌入費不退還：投資隨載體消失，但寶石本身是可回收資產

**共通限制**：任何嵌合操作期間，巫師進入**建造硬直**——無法攻擊、無法閃避
（見建造系統 GDD，provisional）。

## Formulas

### 最終傷害

所有攻擊皆經過此公式：

`FinalDamage = BaseDamage × LevelMult × AffinityMult × (1 − ArmorReduction)`

| 變數 | 符號 | 型別 | 範圍 | 說明 |
|---|---|---|---|---|
| 基礎傷害 | `BaseDamage` | float | 待調 | 該屬性的基準傷害 |
| 等級倍率 | `LevelMult` | float | 1.0 / 1.2 | Lv1 = 1.0，Lv2 = 1.2 |
| 剋制倍率 | `AffinityMult` | float | 0.75 / 1.0 / 1.5 | 抗性 / 無關聯 / 弱點 |
| 護甲減免 | `ArmorReduction` | float | 0–0.75 | 由有效防禦力換算 |

**輸出範圍**：`0.5625` 倍（Lv1 打抗性且高防）至 `1.8` 倍（Lv2 打弱點且無防）。

**關鍵驗算**——確保屬性選擇壓過等級：

```
Lv1 打弱點    = 1.0 × 1.5  = 1.50
Lv2 打無關聯  = 1.2 × 1.0  = 1.20
Lv2 打抗性    = 1.2 × 0.75 = 0.90
```

✅ 用對屬性的 Lv1（1.50）穩穩勝過用錯屬性的 Lv2（0.90），
符合 game-concept §4.1「等級不可輾壓屬性選擇」。

### 有效防禦力（穿甲）

`EffectiveArmor = max(BaseArmor × 0.25, BaseArmor − ΣPenetration)`

| 變數 | 型別 | 範圍 | 說明 |
|---|---|---|---|
| `BaseArmor` | float | ≥ 0 | 敵人原始防禦力 |
| `ΣPenetration` | float | ≥ 0 | 所有生效中的穿甲 debuff 總和（可疊加） |
| 下限係數 | float | 0.25 | **硬性下限**，防禦力永不低於原始的 25% |

**範例**：`BaseArmor = 100`，三座蝕塔各上 30 點穿甲 → `ΣPenetration = 90`

```
max(100 × 0.25, 100 − 90) = max(25, 10) = 25
```

→ 下限生效，防禦力停在 25，多出的穿甲被浪費。**這是刻意的邊際遞減。**

### 雷的跳躍傷害

`JumpDamage(n) = BaseDamage × 0.8ⁿ`，其中 `n` = 跳躍序號（初擊 `n = 0`）

| 跳躍 | 係數 | 傷害 |
|---|---|---|
| 初擊 | 0.8⁰ | 100% |
| 第 1 跳 | 0.8¹ | 80% |
| 第 2 跳 | 0.8² | 64% |
| 第 3 跳 | 0.8³ | 51.2% |
| 第 4 跳 | 0.8⁴ | 41.0% |

**總傷害上限** = 336.2%（全部命中時）。
即使在兩隻敵人間來回彈射，總收益仍收斂於此。

### 風的擊退距離

`KnockbackDistance = BaseKnockback × Random(0.6, 1.4)`

隨機幅度 ±40%。**不疊加**——同一敵人同時被多座風塔命中時，只套用一次擊退。

### 融合

`Lv2 × 1 ← Lv1 × 3`（同屬性）。被消耗的 3 顆實例自庫存移除。

## Edge Cases

### 嵌合操作

- **若嵌合時金錢不足 `C`**：操作被拒絕，UI 以灰化 + 抖動提示
  （沿用 art-bible §4 警示規則，不轉紅），不進入建造硬直。
- **若嵌合過程中巫師被擊殺**：操作中止，金錢不扣除，寶石留在庫存。
- **若嵌合過程中該塔被摧毀**：操作中止，金錢不扣除。
- **若準備期取下後未再嵌入即進入戰鬥**：該塔以基礎攻擊運作，無額外懲罰。

### 融合

- **若同屬性 Lv1 恰好 3 顆且全部已嵌在塔上**：需先取下才能融合。
  準備期取下免費，故無實質阻礙。
- **戰鬥期不可融合。** 融合僅限準備期與關卡外。
  理由：融合會消耗實例，若在戰鬥中執行可能突然讓多座塔失去寶石，造成防線瞬間崩潰。
- **若擁有 Lv1 超過 3 顆**：玩家自選要消耗哪 3 顆。

### 屬性剋制

- **敵人同時擁有弱點與抗性時**：兩者為不同屬性，**不會同時觸發**。
  打中弱點屬性 → ×1.5；打中抗性屬性 → ×0.75；其餘 → ×1.0。
- **基礎塔（無屬性）攻擊任何敵人**：`AffinityMult` 恆為 1.0。
  不吃弱點加成，也不受抗性懲罰。

> ⚠️ **抗性 × 屬性禁用挑戰的死局**
>
> 關卡的敵人抗性組合與該關挑戰目標的禁用項，**必須至少留下兩種可行的屬性解**
> （基礎塔不計入，因其無法觸發弱點）。
>
> 此為**關卡設計的硬性驗證規則**，違反則產生不可達成的星星，
> 牴觸 game-concept §4.3「限制型目標永遠可達成」。

### 疊加與同屬性並存

| 屬性 | 規則 |
|---|---|
| **火** | 燃燒區可疊加，**上限 3 層**。超過部分不生效 |
| **霜** | 減速**不疊加，取最高值**。一次性傷害則每次進入新的減速場皆觸發 |
| **雷** | **可重複命中同一目標**，但總跳躍次數上限 4，且每跳 −20% |
| **風** | 擊退**不疊加**。同時命中時只套用一次，距離取其一 |
| **蝕** | 穿甲**可疊加**，但受 25% 下限約束 |

### 數值邊界

- **`BaseArmor = 0` 的敵人**：`EffectiveArmor = 0`。
  穿甲對無甲敵人無額外效果，蝕退化為普通單體攻擊。
- **`ArmorReduction` 上限 0.75**：即使防禦力極高，傷害減免不超過 75%，
  確保任何攻擊都能造成傷害（呼應「絕不做免疫」原則）。
- **雷在場上僅剩 1 隻敵人時**：所有跳躍集中於該敵人，總傷害仍受 336.2% 上限約束。
- **霜的減速場範圍內無敵人時**：持續維持，不消耗資源，無效果。

### 關卡週期

- **關卡結束（勝或敗）**：所有嵌合狀態清空，寶石全數回庫存，嵌入費不退還。
- **關卡失敗重試**：庫存與寶石等級不變，**無任何懲罰**
  （呼應 game-concept §7 心流設計的低重試成本）。

## Tuning Knobs

| 參數 | 建議起始值 | 過高會怎樣 | 過低會怎樣 |
|---|---|---|---|
| `C`（嵌入費） | 建造費的 **60%** | 玩家不敢嵌合，全場基礎塔 | 嵌合無成本感，基礎塔失去意義 |
| `WeaknessMult` | **1.5** | 不用對屬性等於不能玩 | 剋制失去意義 |
| `ResistMult` | **0.75** | 用錯屬性等同浪費，違反「輕鬆」 | 抗性感受不到 |
| `LevelMult(Lv2)` | **1.2** | 等級輾壓屬性選擇 | 升級沒有價值 |
| `FusionCost` | **3 顆** | MVP 內升不了任何一顆 | 升級太廉價，失去「數量 vs 品質」取捨 |
| `ArmorFloorRatio` | **0.25** | 穿甲效果太弱，蝕失去定位 | 重甲敵人失去質感 |
| `ArmorReductionCap` | **0.75** | 出現實質免疫，違反反支柱⑤ | 防禦力失去意義 |
| `FireStackCap` | **3 層** | 堆滿火塔成為最優解 | 集火沒有價值 |
| `ChainJumps` | **4 次** | 雷過強，壓過其他屬性 | 鏈式特色不明顯 |
| `ChainFalloff` | **0.8** | 雷的總傷害發散 | 跳躍幾乎沒收益 |
| `KnockbackVariance` | **±40%** | 風塔感覺不可靠 | 隨機性感受不到，回到可精算的鎖位 |
| `GemDropPerLevel` | **2 顆** | 收集太快，稀缺感消失 | 湊不滿 5 種，連攜放不出來 |
| `InitialGemCount` | **3 顆**（3 種各 1） | 前期沒有解鎖感 | 前期連攜放不出來，MVP 驗證不了核心循環 |

> ⚠️ **互動警告**：`C` 與 `GemDropPerLevel` 互相牽制——
> 寶石多但嵌不起，或嵌得起但沒寶石，兩種失衡都會讓系統空轉。
> 調整任一項時須同時檢查另一項。

## Acceptance Criteria

### 核心規則

- **GIVEN** 一座已建造但未嵌合的塔，**WHEN** 敵人進入其射程，
  **THEN** 該塔以基礎攻擊（單體、索敵第一隻、基準攻速）攻擊，且 `AffinityMult = 1.0`。
- **GIVEN** 一座已嵌合火寶石的塔，**WHEN** 敵人進入射程，
  **THEN** 該塔停止基礎攻擊，改為週期性投放燃燒區。
- **GIVEN** 玩家擁有一顆已嵌合的寶石，**WHEN** 嘗試將其嵌入第二座塔，
  **THEN** 操作被拒絕。
- **GIVEN** 玩家金錢少於 `C`，**WHEN** 嘗試嵌合，
  **THEN** 操作被拒絕、不扣款、不進入建造硬直，UI 顯示灰化 + 抖動。

### 經濟模型

- **GIVEN** 準備期已嵌合一顆寶石（已扣 `C`），**WHEN** 玩家取下該寶石，
  **THEN** 金錢回復至嵌合前的數額。
- **GIVEN** 戰鬥期已嵌合一顆寶石，**WHEN** 玩家取下該寶石，
  **THEN** 金錢**不**回復，寶石退回庫存。
- **GIVEN** 一座已嵌合的塔，**WHEN** 該塔被敵人摧毀，
  **THEN** 寶石回到庫存，且 `C` 不退還。

### 公式

- **GIVEN** Lv1 火寶石塔攻擊一隻弱火、無甲的敵人，**WHEN** 命中，
  **THEN** 傷害為 `BaseDamage × 1.5`。
- **GIVEN** Lv2 火寶石塔攻擊一隻抗火、無甲的敵人，**WHEN** 命中，
  **THEN** 傷害為 `BaseDamage × 0.9`，**且該值小於**前一項的 `1.5`。
- **GIVEN** 一隻 `BaseArmor = 100` 的敵人身上有總計 90 點穿甲，
  **WHEN** 計算有效防禦力，**THEN** 結果為 `25`（下限生效），而非 `10`。
- **GIVEN** 一座雷塔對兩隻敵人施放且全部跳躍命中，**WHEN** 結算總傷害，
  **THEN** 總和為 `BaseDamage × 3.362`。
- **GIVEN** 一隻敵人同時位於 5 個燃燒區內，**WHEN** 結算燃燒傷害，**THEN** 僅 3 層生效。
- **GIVEN** 一隻敵人同時被 3 座風塔命中，**WHEN** 結算擊退，**THEN** 僅套用一次擊退。

### 融合

- **GIVEN** 玩家擁有 3 顆同屬性 Lv1 寶石，**WHEN** 於準備期執行融合，
  **THEN** 該 3 顆自庫存移除，新增 1 顆同屬性 Lv2。
- **GIVEN** 戰鬥期進行中，**WHEN** 玩家嘗試融合，**THEN** 操作被拒絕。

### 跨系統

- **GIVEN** 場上有一座火塔與一座霜塔，**WHEN** 連攜系統查詢塔屬性，
  **THEN** 正確回傳「火」與「霜」。
- **GIVEN** 玩家嵌合一顆寶石，**WHEN** 操作完成，
  **THEN** 事件匯流排廣播 `OnGemSocketed`，三星挑戰系統能據此更新「本關已使用屬性集合」。
- **GIVEN** 關卡失敗並重試，**WHEN** 進入新一局，
  **THEN** 玩家的寶石庫存與等級與失敗前完全相同。
