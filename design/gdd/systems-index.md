## 3. 循環依賴與解法

### ① 存檔系統 × 所有有狀態的系統

**問題**：存檔要知道存什麼 → 依賴各系統；各系統要載入狀態 → 依賴存檔。

**解法：序列化契約（`ISaveable` 介面）**
存檔系統只認識介面，不認識任何具體系統。存檔因此可位於 L0，各系統實作介面。

### ② 三星挑戰 × 玩法系統

**問題**：挑戰要監控「用了幾座塔」「有無觸發連攜」「有無重新嵌合」，
需要玩法系統回報。但玩法系統不該知道挑戰系統存在——否則每加一個挑戰模板
就要改動核心玩法程式碼。

**解法：事件匯流排（Event Bus）**
玩法系統廣播事件（`OnTowerBuilt`、`OnChainTriggered`、`OnGemSocketed`…），
挑戰系統訂閱。

> 這讓 art-bible §4.2 的**挑戰模板庫**真正可行：
> 新增模板只需訂閱既有事件，不用碰玩法程式碼。

### ③ 巫師能力 × 連攜系統

**問題**：巫師中轉是連攜的一部分，但巫師能力又要主動呼叫連攜（引燃）。

**解法：單向依賴**
連攜系統擁有全部判定邏輯；巫師僅將自己註冊為「中繼節點」。
**巫師 → 連攜**，不反向。

## 4. 瓶頸系統（高風險）

一旦設計錯，會連累大量下游。**值得最多的設計時間。**

| 系統 | 被誰依賴 |
|---|---|
| **事件匯流排** | 所有系統 |
| **塔系統** | 幾乎所有玩法系統 |
| **寶石嵌合** | 連攜、挑戰、貨幣、圖鑑 |
| **連攜系統** | 巫師能力、提示視覺化、挑戰 |

### 葉節點（低風險，可晚做）

設定系統、圖鑑系統、小地圖——無其他系統依賴，做壞了只影響自己。

### v1.0（延後，不影響核心驗證）

| 系統 | 為什麼可以延後 |
|---|---|
| 跨關卡貨幣 | MVP 僅 5 種寶石，隨機性壓力小，尚不需要保底機制 |
| 圖鑑系統 | 敘事是點綴；MVP 用最簡文字即可 |
| 渲染擴充（遮擋描邊） | 體驗優化。MVP 先靠小地圖 + 音效替代 |
| 設定系統 | MVP 僅需音量與基本按鍵 |

### ⚠️ 範圍現實檢查

27 個 MVP 系統，對「單人 + 幾個月 + 首個完整專案」有壓力。

但**系統數量不是工作量的好指標**。真正的重量集中在五個 ★ 系統：

```
寶石嵌合 · 連攜系統 · 巫師能力 · 三星挑戰 · 連攜提示視覺化
```

**這五個就是這款遊戲。** 其餘 22 個是支撐它們的基礎設施，
且多數有標準解法（NavMesh、物件池、存檔序列化皆有現成範本）。

**時間預算建議**：5 個核心系統佔 **60%**、22 個支撐系統佔 **40%**。
若支撐系統吃掉超過一半時間，就是走偏了——該去找現成方案而非自造。

## 8. 傳入的約束（來自上游文件）

| 來源 | 約束 | 影響系統 |
|---|---|---|
| art-bible §7 | 關卡須**小、好記、有地標**；長廊型與視線封閉迷宮型不可用 | 關卡與章節進程 |
| art-bible §4 | 寶石屬性上限約 **8 種**（受色相可分性限制） | 寶石嵌合 |
| art-bible §8 | 所有塔共用單一材質，破損與屬性色透過 **MaterialPropertyBlock** | 塔破損與維修、渲染擴充 |
| art-bible §8 | 遮擋描邊須用 **URP Render Graph API**（6.3 已移除 Compatibility Mode） | 渲染擴充 |
| art-bible §7 | 滑鼠控制視角旋轉，**無自由游標**；格子以準星指向並**自動吸附** | 建造系統、輸入、攝影機 |
| game-concept §3.3 | 提前召喚的獎勵須為**每波固定值**，不可複利累加 | 波次系統 |
| game-concept §4.3 | 挑戰目標**一律限制型**，不可用要求型。⚠️ **此鐵則僅涵蓋目標本身，不涵蓋敵人抗性佈局**——可達成性須另由下方的關卡驗證規則保證，**不得只依賴本條** | 三星挑戰、關卡與章節進程 |
| game-concept §3.5 | **天賦樹與技能樹的前置關係不可跨樹**——被動節點的前置只能是被動節點，技能節點的前置只能是技能節點。保留日後拆分的可能性 | 天賦／技能樹 |
| game-concept §3.2 | 連攜具**方向性**，A→B 與 B→A 為兩個不同技能，資料模型須支援有向鏈路 | 連攜系統 |
| **gem-socketing** | ⚠️ **敵人須新增「防禦力」概念**（`Armor`、`WeakAttribute`、`ResistAttribute` 三欄位），以支撐蝕的穿甲與屬性剋制 | 敵人系統、傷害計算 |
| **gem-socketing** | ⚠️ **關卡的敵人抗性組合 × 挑戰目標禁用項，須至少留下兩種可行的屬性解**（基礎塔不計入）。違反則產生不可達成的星星 | 關卡與章節進程、三星挑戰 |
| **gem-socketing** | 塔僅**單一插槽**；基礎塔（未嵌合）仍具攻擊能力，索敵第一隻、無屬性 | 塔系統 |
| **gem-socketing** | 嵌合需付費 `C`（建造費 60%），準備期取下全額退還、戰鬥期不退還 | 關卡內經濟、建造系統 |
| technical-preferences | Draw Call < 500、60 FPS @1080p | 物件池、VFX、渲染擴充 |
