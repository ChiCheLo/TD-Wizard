## 概念快照

> ⚠️ 這只是對話中的口述紀錄，**不是正式文件**。正式版由 `/brainstorm` 產出至
> `design/gdd/game-concept.md`，屆時以該檔為準。

**一句話**：一款以巫師為主題的 3D 動作塔防，玩家扮演兼任工程師的巫師，在戰場上建造、
嵌合、拆除防禦塔，抵擋波次推進的怪物。

| 要素 | 內容 |
|---|---|
| 類型 | 動作塔防（Action Tower Defense） |
| 視角 | 3D，預設第三人稱，按鍵可切第一人稱（PUBG 式切換） |
| 敵人 | 波次召喚，朝目標推進 |
| 建造 | 玩家在戰場上蓋基礎防禦塔，**準備期與戰鬥期皆可建造** |
| 深度系統 | **寶石嵌合**——鑲嵌不同屬性寶石改變塔的屬性 |
| 湧現系統 | **連攜攻擊**——特定塔之間產生協同效果 |
| 玩家角色 | 巫師＝工程師＋增益者：建造 / 嵌合 / 拆除 / 對塔施法 / **連攜中轉** |

**類型定位**：同類參照為 *Orcs Must Die!*、*Dungeon Defenders*、*Sanctum*。
類型已被市場驗證，差異化需靠「寶石嵌合 × 連攜攻擊」這組系統的深度建立。

## 核心機制定案（2026-09-11）

### Q1 — 巫師定位：弱輸出 ＋ 強增益 ＋ 連攜中轉 ✅

巫師持有魔力資源，**主要價值在於作用於塔，而非自己輸出**：

| 能力 | 作用 |
|---|---|
| 基礎攻擊 | 傷害很低，用於自保與補刀漏網小怪 |
| 過載 | 短時間大幅提升單座塔的輸出 |
| 引燃連攜 | **主動觸發**塔間連攜，而非等待被動條件達成 |
| 護盾 / 緊急維修 | 保住快被打爆的關鍵塔 |
| **連攜中轉** ⭐ | 部分技能可作為連攜的**中繼點**——兩座塔距離過遠無法連攜時，巫師可充當橋樑接通 |

**設計理由**：本作差異化在「寶石嵌合 × 連攜攻擊」。若巫師自己能打得很爽，這兩個系統
會退化成配菜。讓巫師的能力全部作用在塔身上，核心系統才真正成為核心。

**「連攜中轉」的關鍵價值**：它讓**巫師的站位**從無意義變成戰術核心決策。玩家必須思考
「我站哪裡才能把這兩座塔接起來」，這是本作最獨特的機制。

### Q2 — 視角：預設第三人稱，按鍵切第一人稱 ✅

如 PUBG 的 TPS/FPS 切換——**不是兩套不同的操作模式**，而是同一套操作下的視角選擇。
玩家預設第三人稱（全局判讀、建造），需要時按鍵切第一人稱（瞄準、沉浸感）。

### Q3 — 時間取捨：全程可建造，代價是喪失行動力 ✅

- **準備期與戰鬥期都可以建造**，建造規則相同
- **建造時巫師無法攻擊、無法閃避**——等同活靶

**設計理由**：不需要額外的資源懲罰或階段限制，這個代價本身就是動態的。安全時蓋塔沒有
代價；戰鬥中蓋塔則是拿命在賭。遊戲會自己產生平衡，玩家每次都得判斷
*「左路快破了，我現在要冒險補這座塔嗎？」*

## 📌 衍生設計筆記（留給 /brainstorm 與後續 GDD）

1. **連攜中轉 × 建造硬直的互動**
   中轉時巫師是否也需要站定不動？若是，則「當橋樑」與「蓋塔」共用同一種脆弱狀態，
   兩者會互相競爭玩家的行動力預算——這可能是好事（強化取捨），需要實測驗證。

2. **「弱輸出」要多弱？**
   需要數值定義。太弱會讓玩家覺得基礎攻擊是廢的，太強會侵蝕塔的地位。留給 GDD 階段。

3. **手把支援的重新評估**
   移除魔法陣繪製後，原本「手把難以繪製圖形」的疑慮消失了。手把支援的可行性上升，
   可在 `/ux-design` 階段重新評估是否提升為 Full。
